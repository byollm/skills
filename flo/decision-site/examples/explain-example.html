Decision D1 · #1678 / #1645 · iteration reserve

The agent hits its cap with edits not committed

The problem in one breath

1The agent loop has a cap, like 50 iterations. At the cap the run stops.

2If the model just edited a file at 50, it still needs a retest and a commit. That is 2 more steps.

3Today it dies at 51 with uncommitted edits. The "reserve of 3" in the PR is really 1.

Drive it

normal iterationreserve iterationnot allowededit / retest / commitrun dies

What each option does

Reserve of 3, kept across passesproposed

The cap becomes cap + 3. A retest and a commit fit. Needs a test that really runs past the cap.

Exactly 1 extra iteration

This is what the code does now, because limit is re-read each pass. Only one step is granted. Fix the notice text to say 1. A retest plus commit (2 steps) still does not fit.

Drop the reserve

The cap is the cap. The run dies the moment the cap is used, even in the middle of an edit.
